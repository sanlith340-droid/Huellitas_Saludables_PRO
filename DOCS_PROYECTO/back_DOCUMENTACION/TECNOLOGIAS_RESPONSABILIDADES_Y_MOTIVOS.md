No se presentan inferencias como hechos históricos.

## 2. Frontend: presentación, navegación y comunicación con API

### 2.1 React, React DOM y TypeScript

**React — `^18.3.1` (lock `18.3.1`) | Capa: frontend/runtime.** En general, biblioteca para construir interfaces mediante componentes. En el proyecto compone la SPA, su estado/contexto, páginas, formularios, dashboards y piezas reutilizables; arranca desde `src/main.tsx` con `React.StrictMode`. Los guards (`PrivateRoute`, `RoleRoute`) condicionan lo que se presenta, pero no reemplazan la autorización de la API.

- **Motivo documentado:** el documento maestro DT-02 recomienda mantener React y reutilizar las pantallas y patrones existentes.
- **Justificación técnica inferida:** la estructura de páginas/componentes/contexto facilita compartir UI y estado.
- **Motivación histórica:** no se encontró acta de elección original ni comparación contemporánea.
- **Beneficios y límites:** reutilización y composición de UI; no es router, cliente HTTP ni frontera de seguridad. No hay benchmark de frontend.
- **Evidencia:** [`front/src/main.tsx`](../../front/src/main.tsx), [`front/src/App.tsx`](../../front/src/App.tsx), [`front/src/routes/AppRoutes.tsx`](../../front/src/routes/AppRoutes.tsx), [`front/src/context/AuthContext.tsx`](../../front/src/context/AuthContext.tsx), [`front/src/components/`](../../front/src/components), [`front/src/pages/`](../../front/src/pages), [documento maestro, DT-02](ARQUITECTURA_REGLAS_Y_DECISIONES_TECNICAS.md).

### Aclaración fundamental: React, JavaScript y FastAPI

React es una biblioteca de **frontend** ejecutada en el navegador; no reemplaza Node/Express ni es un framework Python. El backend actual está escrito en **JavaScript ESM** y corre en **Node.js** con **Express**. **FastAPI** es un framework de backend para **Python**: no traduce código JavaScript a Python ni migra automáticamente Express. Un cambio a FastAPI exigiría reimplementar el backend, sus rutas, validaciones, reglas, persistencia, autenticación y pruebas en Python. El material auditado no muestra FastAPI instalado/usado ni una decisión adoptada para migrar. No hay benchmark comparativo que permita afirmar que Express o FastAPI sea más rápido en este proyecto.

## 9. Tecnologías futuras/pendientes: no hay elecciones que inventar

La auditoría y el documento maestro dejan necesidades de mejora, pero no establecen necesariamente tecnologías seleccionadas para resolverlas. Por tanto, esta sección registra **requisitos pendientes**, no recomendaciones de librerías adoptadas:

1. **Pruebas frontend y E2E:** incorporar una estrategia automatizada que cubra componentes/flujo de navegador; framework concreto no documentado como elección.
2. **Contrato API:** alinear Swagger/OpenAPI con Bearer JWT y respuestas actuales y automatizar conformidad del contrato; herramienta para ello no elegida.
3. **Seguridad de autenticación:** evaluar rate limiting de login y mecanismo de revocación/invalidez de tokens; no se encontró tecnología escogida.
4. **Gestión de secretos y producción:** retirar fallbacks/placeholders, definir secretos gestionados, HTTPS, backups y operación/observabilidad; proveedor/plataforma de despliegue no definido.
5. **CORS:** establecer allowlist por entorno coherente con comparación literal; la política exacta no debe inferirse del `*` actual.
6. **Calidad/build frontend:** aclarar manifiestos Vite 6 vs raíz Vite 8, elegir configuración única, verificar ESLint y corregir/validar regla CSS sospechosa.
7. **Integridad/persistencia:** mantener schema, migraciones, triggers y SQL sincronizados; documentar procedimiento seguro de migración y prevenir divergencias.
8. **Reproducibilidad:** fijar tags/digests de imágenes y versiones de runtimes apropiadas; no se ha registrado una versión futura específica.

No se presenta ninguno de esos puntos como decisión ya adoptada ni se asigna nombre de producto/librería sin evidencia.

## 11. Relación de responsabilidades y arquitectura modular de tres capas

La solución puede entenderse como tres capas principales con responsabilidades separadas, más seguridad/calidad/operación transversales:

1. **Presentación (frontend):** React/React DOM renderizan la SPA; TypeScript aporta tipos de desarrollo; React Router enlaza URL con páginas/layouts; Axios comunica con la API; CSS y fuentes componen la presentación. Nginx entrega el build y proxya rutas API. El cliente guía la experiencia por rol, pero nunca decide por sí solo la autorización real.
2. **Aplicación/API (backend):** Node.js ejecuta JavaScript ESM; Express compone middlewares y rutas HTTP/JSON; Joi valida entradas; servicios/controladores implementan reglas y respuestas; JWT identifica al usuario y el middleware consulta rol vigente. La API es la frontera de confianza y debe validar/autorización en servidor.
3. **Persistencia (datos):** PostgreSQL conserva el modelo relacional e invariantes. Prisma schema/Client y migraciones soportan modelo declarativo y CRUD; SQL/PLpgSQL complementa objetos no expresados plenamente por Prisma y operaciones de bloqueo/concurrencia.

**Transversales:** seguridad incluye hashing, tokens, CORS, redacción y parametrización SQL; pruebas backend con Vitest/Supertest ejercitan módulos, HTTP y BD; OpenAPI documenta el contrato aunque hoy requiere alineación; Docker/Compose organizan entorno local/test. No se atribuye producción lista al stack: los documentos describen desarrollo/demo y dejan pendientes secretos, TLS, backups, operación y estrategia de despliegue.

## 12. Alcance y limitaciones de la consolidación

Este documento combina inventarios estáticos y hallazgos aportados por auditorías de varios dominios. Las rutas enlazadas son relativas al repositorio, partiendo de `docs/back/`. Los números de versión distinguen manifiesto/rango y lock cuando ambos estaban disponibles; versiones de imagen se citan por tag. No se validó que los servicios estén ejecutándose ni que cada script/estilo/configuración funcione en runtime. Los resultados históricos de bitácoras no se presentan como ejecuciones actuales. Antes de tomar decisiones de mantenimiento conviene contrastar cada enlace con el checkout vigente.
